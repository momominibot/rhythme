**The gate is useful, but release isolation, consent coverage and Part 2 need changes.** I reproduced 139 passing core checks and the consent defect below. Browser and static suites were not rerun under this session’s read-only restriction.

**1. Workflow: two release-control issues, followed by hardening.**

- **P1: PRs can displace releases.** [.github/workflows/deploy.yml:17](/Users/michiyomimi/Doubao/chats/2026-10-16/new-chat-12/ovumind/.github/workflows/deploy.yml:17) shares one concurrency group across PRs and releases. A newer PR can replace a pending main run despite `cancel-in-progress: false`. Separate PR/ref testing groups and serialize deployment separately. [GitHub concurrency](https://docs.github.com/en/actions/concepts/workflows-and-actions/concurrency).
- **P1: main-only deployment is unenforced.** `deploy.yml:55` excludes PRs but allows dispatches targeting other refs. Add `github.ref == 'refs/heads/main'`. Environment restrictions and required-check settings remain unverified. [Dispatch semantics](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_dispatch).
- Permissions are sufficient but overbroad: tests inherit Pages/OIDC write privileges (`deploy.yml:12`). Move these into `deploy`. Fork PRs normally have read-only tokens, no secrets, and may require approval; these tests need neither secrets nor deployment privileges. [GitHub fork behavior](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#pull_request).
- Playwright is pinned, [1.63.0 exists](https://pypi.org/project/playwright/1.63.0/), and matching browser installation is correct (`deploy.yml:48`). Add `--only-shell`, installation/job timeouts and failure artifacts. Downloads still depend on external mirrors. OS/runtime versions and action tags float; pin supported versions and action SHAs. [Playwright installation](https://playwright.dev/python/docs/browsers#chromium-headless-shell), [GitHub pinning](https://docs.github.com/en/actions/reference/security/secure-use).
- Failed prerequisites skip deployment through `needs` (`deploy.yml:56`), leaving the previous site untouched by that run. This is not automatic rollback after deployment itself fails. Protect workflow/test changes and require both test jobs for merges. [Dependency semantics](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_idneeds).
